# Homelab Projects

Скрипт генерирует статическую страницу `index.html` со списком всех репозиториев
GitHub-аккаунта — публичных и, если токен принадлежит этому же аккаунту, приватных:
название, ссылка, назначение из README (максимум 3 строки) и результат (`WIP` по
умолчанию). Оформление — палитра темы VS Code **Monokai Dimmed**, без фреймворков,
интерактивности и анимаций.

## Требования

- Node.js 18+ (используется встроенный `fetch`).
- Токен GitHub — по желанию, но с ним лимит API выше (5000 вместо 60 запросов/час)
  и доступны приватные репозитории. Приватные попадают в список только тогда, когда
  токен принадлежит запрашиваемому аккаунту и имеет scope `repo`: в этом случае
  используется эндпоинт `/user/repos`; для чужого аккаунта GitHub отдаёт только
  публичные репозитории. Скрипт берёт `GITHUB_TOKEN`, затем `GH_TOKEN`,
  затем токен из `gh auth token` (если GitHub CLI авторизован — приватные
  подхватываются автоматически).

## Запуск

```bash
node generate.js
# или
npm run generate
```

Пользователь по умолчанию — `amartyanovx` (`DEFAULT_USER` в начале `generate.js`).
Переопределения:

```bash
node generate.js other-user
GITHUB_USER=other-user node generate.js
GITHUB_TOKEN=ghp_xxx node generate.js
```

После запуска рядом со скриптом появляется (перезаписывается) `index.html`.

## Настройка

Все константы — в начале `generate.js`:

- `DEFAULT_USER` — чей GitHub показывать;
- `DEFAULT_RESULT` — текст результата в каждой плашке (`WIP`);
- `INCLUDE_PRIVATE` — включать приватные репозитории (`true`);
- `EXCLUDED_REPOS` — имена репозиториев, которые не попадают в список
  (по умолчанию `['homelab-projects']`, чтобы страница не перечисляла сама себя);
- `MAX_PURPOSE_LENGTH` — предельная длина назначения из README;
- палитра и стили — в `renderPage()` (CSS-переменные `--bg`, `--fg`, `--link` и т.д.).

Назначение берётся из первого осмысленного абзаца README (заголовки, бейджи,
картинки и блоки кода пропускаются). Если README нет — используется описание
репозитория. Плашка ограничивает текст тремя строками и через обрезку в скрипте,
и через CSS (`-webkit-line-clamp: 3`). Отступ снизу у плашки — `24px`.

Публичные репозитории идут первыми, приватные — ниже (внутри групп по алфавиту).
У приватных вместо ссылки на репозиторий выводится текст `Private`, заголовки
карточек некликабельны.

## Публикация на GitHub Pages

**Вариант 1 — GitHub Actions (рекомендуется, страница обновляется сама):**

1. Запушьте репозиторий на GitHub.
2. Settings → Pages → Source: **GitHub Actions**.
3. Workflow `.github/workflows/pages.yml` сгенерирует страницу и задеплоит её
   при пуше в `main`, по расписанию (раз в сутки) и вручную.
   Чтобы в сборку попадали приватные репозитории, создайте PAT со scope `repo`
   и сохраните его секретом `HOMELAB_TOKEN` (Settings → Secrets and variables →
   Actions): workflow берёт `secrets.HOMELAB_TOKEN || secrets.GITHUB_TOKEN`.
   Без этого секрета workflow деплоит уже закоммиченный `index.html` — то есть
   страницу, сгенерированную локально со всеми приватными репозиториями.

**Вариант 2 — из ветки:**

Settings → Pages → Source: **Deploy from a branch** → ветка `main`, папка `/ (root)`.
Готовый `index.html` и `.nojekyll` уже лежат в репозитории.

> **Внимание:** страница на GitHub Pages публична. Если в список попадают приватные
> репозитории, их названия, ссылки и описания из README будут видны всем. Чтобы
> этого избежать, поставьте `INCLUDE_PRIVATE = false` или не публикуйте страницу.

## Структура

```
generate.js                     генератор страницы
index.html                      сгенерированная страница (для Pages)
.nojekyll                       отключает обработку Jekyll на GitHub Pages
package.json                    npm-скрипты генерации
.github/workflows/pages.yml     сборка и деплой на GitHub Pages
```
